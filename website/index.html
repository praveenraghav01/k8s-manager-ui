Bring your own LLM

An AI assistant that actually reads your cluster

Pick your model in the top toolbar and ask in plain English — “why is this pod not ready?” or “any warning events in kube-system?”. It runs an agentic tool-use loop over read-only cluster data and streams the answer back token by token.

  • Read-only by design — it can never modify your cluster; it shows you the kubectl command when a change is needed.
  • Grounded in live data — calls tools like logs, events and describe to base every answer on your real cluster.
  • Secrets redacted — secret values are stripped from tool output before anything reaches the API.
  • Provider-agnostic — connects to any OpenAI-compatible endpoint (TrueFoundry, OpenAI, Azure, LiteLLM…) and stays aware of your current view.
Needs your own LLM subscription. The assistant ships with no built-in model — you connect an OpenAI-compatible API (TrueFoundry, OpenAI, Azure OpenAI, LiteLLM, …), which usually requires a paid account and API key. Your key is stored locally in ~/.config/k8s-manager/config.json. Everything else in the app works without it.

Install & first launch

macOS

Download the Apple-Silicon .dmg, open it and drag k8sight to Applications.

The build is ad-hoc signed (no Apple Developer ID), so on first launch right-click the app → Open. If macOS says it’s “damaged” after downloading, clear the quarantine flag:

Terminal
xattr -dr com.apple.quarantine "/Applications/k8sight.app"
Windows

Download the .exe installer and run it. Because the build is unsigned, SmartScreen may warn — choose More info → Run anyway. k8sight installs per-user and adds a Start-menu entry.

Linux

AppImage — make it executable and run:

Terminal
chmod +x k8sight-*.AppImage
./k8sight-*.AppImage

Debian / Ubuntu — install the .deb:

Terminal
sudo dpkg -i k8sight_*_amd64.deb
Requirements
  • kubectl installed and on your PATH (the app shells out to it).
  • A valid ~/.kube/config with at least one context.
  • metrics-server in-cluster for live CPU/memory graphs (optional).

k8sight reconstructs your login-shell PATH at launch, so tools installed via Homebrew, asdf or ~/.local/bin are found even when launched from the Dock.

Connecting clusters

Local kubeconfig contexts

k8sight reads every context in ~/.kube/config. Use the context selector in the sidebar to switch clusters, and pin the ones you use often to the left-hand rail for one-click quick-switch.

Amazon EKS

Open Add cluster → AWS. k8sight uses the AWS SDK with your existing credentials (env vars, shared config or SSO) to list EKS clusters across regions, then generates a short-lived token and merges the entry into your kubeconfig. No aws CLI required.

Azure AKS — browser or CLI

Open Add cluster → Azure and choose a sign-in method:

  • Browser (recommended) — k8sight opens your system browser and signs in with the OAuth auth-code + PKCE flow. This uses your normal SSO session and satisfies device Conditional Access policies, with no az install.
  • Azure CLI — if you already use az login, k8sight can drive the CLI instead.

It then lists clusters across your subscriptions and pulls user (or admin) credentials into your kubeconfig.

AI assistant & agents

Connect an LLM

The assistant needs your own OpenAI-compatible endpoint. In Preferences → AI, set the base URL, model and API key (TrueFoundry, OpenAI, Azure OpenAI, LiteLLM, …). Values are stored locally in ~/.config/k8s-manager/config.json.

Or set them as environment variables:

Env
LLM_BASE_URL=https://api.your-provider.com/v1
LLM_API_KEY=sk-…
LLM_MODEL=gpt-4o-mini
Docked coding agents

k8sight detects coding agents on your PATH — Claude Code, GitHub Copilot CLI, Gemini CLI, Codex and opencode — and opens the chosen one in a docked panel beside the pod terminal. Pick the default in Preferences → External Tools; the top toolbar then shows that agent’s icon and name. Agents run as local processes with their own authentication.

MCP server

k8sight exposes its read-only cluster tools over the Model Context Protocol so your own agents can use them. Run the stdio server with:

Terminal
npm run mcp

Write tools are off by default — the server is read-only unless you explicitly enable them.

Build & release

Run from source

Clone the repo, install dependencies and start the dev servers with hot reload:

Terminal
npm ci
npm ci --prefix client
npm run dev
Package the desktop app

Build installers for the current OS with electron-builder:

Terminal
npm run dist   # artifacts land in release/

The macOS build is ad-hoc signed with the hardened runtime automatically.

Cut a release (GitHub Actions)

Pushing a v*.*.* tag runs the Build & Release workflow across macOS, Windows and Linux and publishes the installers to a GitHub Release:

Terminal
git tag v1.3.0
git push origin v1.3.0
